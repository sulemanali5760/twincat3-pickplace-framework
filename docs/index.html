One call runs the whole machine

The machine is a tree of nodes. A single Cyclic() on the root reaches every device; a single SetMode() pushes the operating mode to all of them. Watch both happen.

This page is an illustration, not the program. The framework is written in Structured Text and runs on a PLC. What you see here is a JavaScript model of the same logic, slowed down so the call order is visible — a real task scans every 10 ms, far faster than the eye.

What to notice

Nothing wires the tree together. A child registers itself with its parent the moment it is declared — fbLift : FB_PneumaticCylinder(ipParent := THIS^, sNodeName := 'Lift'); — so writing the declaration is building the machine. There is no registration list to keep in step.

Manual and Homing do nothing here, on purpose. Press them. FB_ModeNode dispatches to RunManual() and RunHoming(), but this demo's handling unit never overrides them, so the base class's empty default runs. A unit implements only the modes it actually needs.

The cylinders keep running in Stop. They extend FB_CyclicNode, not FB_ModeNode, so they are not mode-dispatched at all — they hold their last commanded position while the sequence above them resets. That separation is why a device driver can be reused in any machine.

The sequence, step order and stroke timing mirror FB_HandlingUnit and FB_CycleManager in the repository.
